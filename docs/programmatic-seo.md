# プログラマティックSEOの実装順

## 第1段階：発見・更新の基盤（実装済み）

- `/sitemap.xml` を固定ファイルから動的なサイトマップ索引へ変更。
- `/sitemaps/pages.xml` に既存の主要ページと梅田・難波の主要条件ページを掲載。
- 公開対象店舗と公開済み記事は、IDの1,000件区間で分割。新規追加で既存URLの所属をずらさない。
- 店舗は `Shop.public_listing` に合わせる。未承認・一般の保留は除外するが、公開画面で注意喚起している「禁煙報告対応済み店舗」は残す。
- 記事は `Article.published` に合わせ、予約公開前・下書きを除外。
- レコードの更新日時を `lastmod` に使用。固定ページには推測した更新日を付けない。
- DB照会は索引でIDのみ、分割ファイルでURL識別子と更新日時のみを取得。画像・本文・関連モデルを読み込まない。
- アプリとHTTPのキャッシュは各5分。更新が反映されるまで通常最大約10分（アプリ・HTTPキャッシュが重なる場合）。ジョブ・手動再生成は不要。
- ホストは `https://suelog.jp` に固定し、空の区間は404を返す。
- `public/sitemap.xml` を復活させないこと。Railsの静的ファイル配信が動的ルートより優先されるため。
- 旧 `rails sitemap:refresh` は明示的に停止。現在は公開URLから取得する。

確認先：`/sitemap.xml` → `/sitemaps/pages.xml` と店舗・記事の分割ファイル。
Search Consoleにすでに同じサイトマップURLを登録していればURL変更は不要。検出・インデックス登録・検索順位は別途確認する。

## 第2段階：地域・駅ページ

- 現在の登録店舗を市区町村・駅別に集計し、表記揺れを整理する。
- 既存の梅田・難波の専用URLを維持し、店舗数が十分ある地域・駅から追加する。
- 地域範囲・駅の対応を明示し、別地域の同名駅・曖昧な文字列一致を避ける。
- 公開の判断基準を設定し、0件・少数・重複ページを機械的に大量生成しない。
- 地域固有の件数・喫煙条件・確認状況を実データから表示し、主要ページからリンクする。

## 第3段階：条件別ページと内部リンク

- 需要と掲載店舗がある地域×ジャンル、地域×喫煙条件を順に追加。
- URL・canonical・検索用フィルターのnoindexを一貫して管理。
- 地域→条件→店舗、店舗→地域・近隣駅への導線とパンくずを整備。
- 公開基準を満たすページだけサイトマップに追加する。

## 第4段階：計測・改善

- Search Consoleでページ種別ごとの表示回数・クリック・登録状況を比較。
- 流入のあるページから固有情報・情報確認・タイトルを改善。
- 重複・薄いページの統合、掲載基準の調整を行う。
