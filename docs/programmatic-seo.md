# プログラマティックSEOの実装順

## 第1段階：発見・更新の基盤（実装済み）

- `/sitemap.xml` を固定ファイルから動的なサイトマップ索引へ変更。
- `/sitemaps/pages.xml` に既存の主要ページと梅田・難波の主要条件ページを掲載。
- 公開対象店舗と公開済み記事は、IDの1,000件区間で分割。新規追加で既存URLの所属をずらさない。
- 店舗は `Shop.public_listing` に合わせる。未承認・一般の保留は除外するが、公開画面で注意喚起している「禁煙報告対応済み店舗」は残す。
- 記事は `Article.published` に合わせ、予約公開前・下書きを除外。
- レコードの更新日時を `lastmod` に使用。固定ページには推測した更新日を付けない。
- DB照会は索引でIDのみ、分割ファイルでURL識別子と更新日時のみを取得。画像・本文・関連モデルを読み込まない。
- アプリとHTTPのキャッシュは各5分。更新が反映されるまで通常最大約10分（アプリ・HTTPキャッシュが重なる場合）。ジョブ・手動再生成は不要。
- ホストは `https://suelog.jp` に固定し、空の区間は404を返す。
- `public/sitemap.xml` を復活させないこと。Railsの静的ファイル配信が動的ルートより優先されるため。
- 旧 `rails sitemap:refresh` は明示的に停止。現在は公開URLから取得する。

確認先：`/sitemap.xml` → `/sitemaps/pages.xml` と店舗・記事の分割ファイル。
Search Consoleにすでに同じサイトマップURLを登録していればURL変更は不要。検出・インデックス登録・検索順位は別途確認する。

## 第2段階：地域・駅ページ（実装済み）

- `/areas` を市区町村・駅の入口とし、`/areas/:slug` と `/stations/:slug` を追加。
- 既存の梅田・難波とその駅専用URLは維持し、同じ駅の新規URLを重ねて作らない。
- 対象地域・駅の定義は `config/seo/geographies.json`。住所の市区町村境界と、駅ごとに定めた市区町村で対象を限定する。別府県や別地域の同名駅を混ぜない。
- 最寄駅欄は末尾の「○○駅から○m」または駅名そのものを照合し、アクセス説明の途中に出てくる駅を採用しない。全角数字や括弧を正規化し、明示した別名を吸収する。元の住所・最寄駅は変更しない。
- 同名で離れたJR／大阪メトロの平野駅、JR／阪急の吹田駅など、登録文だけでは区別が難しい駅は今回の対象外。
- 公開対象は承認済み・保留でない店舗。地域・駅に10件以上あれば地域一覧・内部リンク・サイトマップに掲載する。10件は運用上の初期基準であり、Googleの必要条件ではない。
- 1〜9件の既知ページはnoindexで表示し、0件・未定義のURLは404。絞り込み・並べ替え・ページ送り・営業中フィルターはnoindex。正規URLは地域・駅の入口へ固定する。
- 地域固有の店舗件数と上位ジャンルを表示し、各店舗の確認状況・喫煙条件の確認を促す。確認済みでない情報を確認済みと表現しない。
- ホーム→地域・駅一覧→地域／駅→店舗、店舗→地域／駅、地域↔駅のリンクを追加。パンくずとBreadcrumbListを出力する。
- 件数と駅の対応は必要な属性だけの一括照会を5分キャッシュ。駅の一覧はキャッシュのIDに加え、現在の承認・保留状態と住所範囲でも絞り込む。住所・最寄駅の編集や新規追加は最長約5分で集計に反映される。
- 地域・駅ページのサイトマップ掲載可否は、集計・サイトマップ・HTTPのキャッシュが重なると最長約15分で反映される。
- 定義済み市区町村・駅の掲載可否と件数は自動更新される。新しい地理範囲や駅を対象にするときは定義を追加する。あらゆる組み合わせの無制限生成はしない。

## 第3段階：条件別ページと内部リンク（実装済み）

- 地域・駅に `/genre/:slug` と `/smoking/:slug` を追加。ジャンルは居酒屋、カフェ・喫茶店、バー・パブ、焼肉、焼き鳥、ラーメン、寿司、和食・日本料理の8種類。喫煙条件は席で喫煙可、喫煙所あり、加熱式のみ対応の3種類。
- 掲載10件以上、親ページから3店舗以上の差、親の90%以下という運用基準を満たす条件ページだけ内部リンクと `/sitemaps/geographic-facets.xml` に掲載する。この基準は検索エンジンの保証や必須条件ではない。
- 親とほぼ同じ集合は親へ、地域・駅・別条件と完全に同じ集合は先に採用したURLへcanonicalを向け、noindex。地域、駅、ジャンル定義、喫煙条件定義の順に判定する。薄いページはnoindex、0件と未定義は404。
- ジャンル集計とSQL絞り込みは共通のトークン区切りを使用。別名・自由入力ジャンルも明示した語と一致させ、部分一致で別ジャンルを混ぜない。
- 喫煙条件別ページは未確認フラグ付き店舗を除外。公開バッジと同じく、2つ目の条件は詳細スケジュールが有効なときだけ採用。状況依存の注記がある条件は断定せず対象外。加熱式のみはすべての有効条件が加熱式限定の場合だけ採用し、紙たばこや不明な条件を混ぜない。
- 喫煙できる時間・曜日・席の制限は既存の店舗カードと詳細に表示する。条件別ページを「今吸える」「全席」「終日」とは表現しない。条件の変更は一覧表示時にも再判定し、集計キャッシュが残っていても該当しなくなった店舗を表示しない。
- 集計は必要な属性の一括照会を5分キャッシュ。地域数や条件数に比例するDB照会はしない。条件ページ表示時の再判定も一括照会し、店舗ごとの照会はしない。
- 地域・駅→ジャンル／喫煙条件→店舗、店舗→該当する地域・駅の条件ページ、地域↔駅で同じ条件へのリンクを追加。基準未達・重複ページへのリンクは生成しない。タイトル、説明、パンくず、canonicalも条件ごとに出し分ける。
- 自由な複数条件の組み合わせURLは生成しない。追加の検索条件・並べ替え・ページ送りは従来どおりnoindexで正規URLへまとめる。サイトマップ索引から新しい条件別ファイルへ自動接続する。
- 定義済み地域・駅・条件は店舗の追加に応じて自動で掲載可否が変わる。掲載基準のキャッシュ反映は第2段階と同じく最大約15分。新しい条件や地域は明示的に定義を追加する。

## 第4段階：計測・改善

### SEOページの管理一覧（実装済み）

- 管理メニュー「SEOページ」から `/panel_8m4k/seo_pages` を開く。既存の管理者認証が必要で、no-store・noindexヘッダーを付ける。
- 定義済みの地域・駅と、各ジャンル・喫煙条件の候補を0件のものも含めて表示。従来の梅田・難波ページ、店舗詳細、記事は対象外。
- URL、店舗数、親の店舗数、サイト側のindex対象／noindex／404対象、判定理由、canonicalを表示。404対象はcanonicalなし。
- 理由は、掲載基準を満たす、掲載店舗なし、店舗数が基準未満、親ページとの差が小さい、同じ店舗集合のページあり。公開用の判定処理から理由を返し、管理画面だけの独自ルールを作らない。
- キーワード、ページ種別、判定、理由で絞り込み。店舗数の昇順／降順、URL順で並べ替え、50件単位でページ送りする。件数サマリーは絞り込み前の全候補を示す。
- 公開用の5分キャッシュを共有し、候補URLごとのHTTPアクセスやDB集計は行わない。キャッシュ未作成時も必要属性の一括照会1回で集計する。店舗の登録・編集によって候補数・判定が自動更新される。
- 「index対象」はサイト側の設定で、Googleでのインデックス登録確認ではない。Search Console APIへの接続は未実装。検索実績は次項のCSV取り込みで照合する。

### 検索実績のCSV照合（実装済み）

- 同じ管理画面の「ページ別CSVを取り込む」から、Search Consoleの通常のページ別CSVをアップロードする。日本語・英語の5列（ページ、クリック数、表示回数、CTR、掲載順位）、UTF-8・BOM、各5MB以下に対応。日付比較モードのCSVやZIPそのものは対象外。
- 対象期間の開始日・終了日と検索条件メモを入力する。比較期間は任意で、指定するときは同じ検索条件・同じ日数の前の期間のCSVを別に添付する。CSV単体から期間やフィルター条件は検証できないため、画面で明示して記録する。
- `https://suelog.jp` の既知のSEO候補URLと照合。別ホスト、店舗・記事、クエリやフラグメント、HTTP、末尾スラッシュ違いなどを勝手に正規化・合算しない。一覧対象外の行数を表示し、一致するURLが0件の取り込みは保存しない。
- 重複URL、不正な数値・列数・文字コード、50,000行超のCSVは拒否。両ファイルを検証してから、取り込み情報と一致したページ指標だけを1トランザクションで保存する。生CSVは保持しない。再取り込みで過去データを上書きせず、最近20回の履歴から切り替えられる。
- 表示回数・クリック数・CTR・平均掲載順位、前期間比を一覧に追加。CTRはクリック数÷表示回数、CTR差はパーセントポイント、順位差は対象期間−比較期間（小さいほど上位）。表示0回のCTR・順位、片方に行がない比較は「—」「比較なし」とする。
- CSVに含まれないページを0クリックや未登録と断定しない。Googleの通常エクスポートは1,000行に切り捨てられるため、欠落は「対象期間のデータなし」と表示する。取り込み行の合計をサイト全体の検索実績とは表現しない。
- index対象の確認候補：表示100回以上・CTR1%未満・平均20位以内、前期間10クリック以上から30%以上の減少、表示100回以上・平均10位超〜20位。noindex・404対象に表示実績がある場合は「掲載設定を確認」として別扱い。これらは運用上の目安で、Googleの評価基準ではない。
- 実績あり／なし、改善候補で絞り込み、クリック数・表示回数・CTR・順位・クリック増減で並べ替えられる。実績は選んだ取り込みから一括照会し、行ごとのDB照会は増やさない。
- マイグレーションで `search_console_imports` と `search_console_page_metrics` を追加。Renderの既存ビルド手順で適用される。CSV取り込みは管理者認証と既存CSRF保護の対象で、管理画面はno-store・noindexを維持する。
