# 公開店舗検索の表記揺れ

一覧のキーワード・最寄駅、地図のキーワード・最寄駅で ShopKeywordSearch を共用する。
全半角・英字大小・かなを正規化する。Unicodeの句読点・記号・空白（縦棒、スラッシュ、アンダースコア、括弧、改行、絵文字等）を入力の区切りとして扱い、各単語をAND照合する。保存側はそれらの区切りを取り除いて照合する。長音と小さい「ェ」等は保持し、意味の異なる語をむやみに同一視しない。
難波/なんば、中百舌鳥/なかもず等の有限の別表記辞書を持つ。任意の漢字の読み・タイプミスを推測する機能ではない。

一覧は既存11項目、地図は従来の店名・住所・ジャンル・最寄駅を対象にする。複数キーワードはAND。駅指定は最寄駅だけを対象とする。
承認・公開条件、エリア・ジャンル・喫煙条件、地図範囲、ページ送りは維持する。元データ・表示テキストは変更しない。

一覧用の keyword_search_text / keyword_station_text は保存前に更新する派生データで、公開JSONには含めない。
マイグレーションは200件単位で既存データを更新し、updated_atや元の店舗情報は変更しない。SQLite/PostgreSQL共通SQLを使用する。
コールバックを通らない一括挿入のNULL値には、現在の絞り込み範囲だけRuby側で照合するフォールバックを持つ。NULL行用の部分インデックスを用意する。
一括更新で検索対象の元データを変える場合は、同時に両派生列をNULLにするか通常のsaveを使う。辞書・正規化ルールを変更する場合も既存派生データを再生成すること。

例: `立ち寿司ホルモン 新鮮や！｜近鉄日本橋` と `立ち寿司ホルモン 新鮮や 近鉄日本橋` の両方で店名・駅名を照合する。記号だけの入力は全件検索にしない。20261128000200で既存の派生文字列も再生成する。
